### 1.1 ตั้งโครงโปรเจกต์ — เสร็จ

- monorepo npm workspaces: `apps/pos`, `apps/order`, `packages/shared`, `backend`
- PocketBase + schema 7 collections + กฎแยกข้อมูลระหว่างร้าน
- unique index บน `orders.client_uuid` — กันบิลซ้ำ
- เส้นทางสาธารณะ `/api/public/shop/:code` สำหรับหน้าลูกค้า
- สคริปต์ `seed.mjs` และ `verify-isolation.mjs`

### 1.2 เข้าระบบด้วย PIN — เสร็จ

- [x] หน้าตั้งค่าเครื่องครั้งแรก — กรอกรหัสร้าน + PIN เจ้าของ (ต้องมีเน็ต)
- [x] ลงทะเบียนเครื่องและจองช่วงเลขบิล (จองที่เซิร์ฟเวอร์ก่อนบันทึกลงเครื่อง)
- [x] หน้าล็อก — เลือกชื่อพนักงาน แล้วกด PIN บนแป้นตัวเลขใหญ่
- [x] เข้าระบบตอนออฟไลน์ได้ หลังพนักงานคนนั้นเคยเข้าครั้งแรกตอนมีเน็ตแล้ว
- [x] เก็บ token ไว้ข้ามการปิดเปิดแอป
- [x] ล็อกหน้าจออัตโนมัติเมื่อไม่มีการใช้งาน (5 นาที)
- [x] จำกัดจำนวนครั้งที่กด PIN ผิด — มีผลทั้งตอนมีเน็ตและไม่มีเน็ต

**ทดสอบกับของจริงแล้ว:** ปิด PocketBase ทั้งตัวแล้วพนักงานยังเข้าระบบด้วย PIN ได้
และหน้าจอแสดงว่ายืนยันตัวตน "จากข้อมูลในเครื่อง"

**ขอบเขตของ PIN ที่ต้องเข้าใจตรงกัน:** PIN 4 หลักมีความเป็นไปได้ 10,000 แบบ
คนที่ถือแท็บเล็ตและเปิด devtools เป็น ย่อมงัดได้ในที่สุด PIN จึงมีไว้เพื่อ
ระบุว่าใครขายบิลไหน และกันการหยิบเครื่องคนอื่นมากดเล่น **ไม่ใช่เครื่องกันขโมยแท็บเล็ต**
สิ่งที่กันการไล่เดาคือการจำกัดจำนวนครั้ง ไม่ใช่ความหนักของการแฮช

### 1.3 เมนู + หมวด — เสร็จ

- [x] เจ้าของร้านเพิ่ม/แก้/ลบหมวดและเมนู อัปโหลดรูปได้
- [x] ปุ่ม "ของหมด" ใช้ได้ตอนออฟไลน์ผ่านคิวส่ง
- [x] ลบหมวดที่ยังมีเมนูไม่ได้ พร้อมบอกจำนวนที่ค้างอยู่
- [x] พนักงานทั่วไปกดได้แค่ "ของหมด" แก้ราคาไม่ได้ (บังคับที่หน้าจอ)
- [ ] จัดลำดับเมนูด้วยการลากวาง — ตอนนี้เรียงตามลำดับที่เพิ่ม

**เส้นแบ่งที่ตั้งใจ:** การแก้เมนูต้องมีเน็ต ส่วน "ของหมด" ต้องใช้ได้ตอนออฟไลน์

เจ้าของร้านแก้เมนูตอนว่าง ไม่ใช่ตอนลูกค้าต่อคิว การบังคับให้มีเน็ตจึงไม่กระทบการขาย
และแลกมาด้วยการที่เราไม่ต้องทำระบบรวมความขัดแย้งเวลาสองเครื่องแก้เมนูตัวเดียวกัน
พร้อมกันตอนออฟไลน์ ซึ่งซับซ้อนมากเทียบกับประโยชน์ที่แทบไม่มี

ส่วน "ของหมด" พนักงานกดกลางวันขายดีตอนที่เน็ตร้านอาจไม่ดี ถ้ากดไม่ได้
ลูกค้าจะสั่งของที่ไม่มีผ่าน QR แล้วร้านต้องไปขอโทษทีหลัง

**ทดสอบกับของจริงแล้ว:** ปิด PocketBase → กด "ของหมด" ได้ทันที งานค้างในคิว →
เปิดเซิร์ฟเวอร์กลับมา → คิวไหลเองและค่าบนเซิร์ฟเวอร์เปลี่ยนจริง

### 1.4 หน้าขาย — เสร็จ

- [x] เลือกหมวด → กดเมนู = 2 แตะถึงตะกร้า ปุ่มสูง 96px ไม่มี dropdown
- [x] ตะกร้า: รวมจำนวนเมนูเดียวกัน เพิ่ม/ลด/ลบ แสดงยอดต่อบรรทัด
- [x] ของหมดกดไม่ได้ — กันการขายของที่ไม่มีตั้งแต่ต้นทาง
- [x] ส่วนลดท้ายบิล จำกัดไม่ให้เกินยอดรวม (บิลติดลบไม่มีความหมาย)
- [x] รับเงินสด + ปุ่มเงินด่วน (พอดี/ธนบัตรที่พอจ่าย) + คิดเงินทอน
- [x] รับเงินน้อยกว่ายอดบิลปิดบิลไม่ได้
- [x] ยกเลิกบิลเป็นสถานะ void ไม่ลบทิ้ง
- [ ] แก้ไข/ดูบิลย้อนหลังจากหน้าจอ (ตรรกะพร้อมแล้ว ยังไม่มีหน้าจอ)
- [ ] ใส่หมายเหตุรายบรรทัดจากหน้าจอ (ตรรกะพร้อมแล้ว)

**ทดสอบกับของจริงแล้ว:** ปิด PocketBase → ขายได้ปกติ 2 บิลติด ยอดและเงินทอนถูก
→ เปิดเซิร์ฟเวอร์กลับมา → คิวไหลเอง บิลถึงเซิร์ฟเวอร์ครบ 4 ใบโดยไม่มี client_uuid ซ้ำ

### 1.5 PromptPay QR — เสร็จ

- [x] สร้าง payload EMVCo ในเครื่อง (ทดสอบกับ CRC check value มาตรฐานแล้ว)
- [x] เรนเดอร์เป็นภาพ QR บนหน้าจอ (พื้นขาวเสมอ ไม่ตามธีมมืด)
- [x] หน้ารับเงินแสดง QR ตามยอดบิล ใช้ได้ตอนออฟไลน์
- [x] ร้านที่ยังไม่ตั้งเลขพร้อมเพย์ได้ข้อความบอกให้รับเงินสดไปก่อน
- [ ] ยืนยันการจ่ายอัตโนมัติ — ต้องเชื่อม API ธนาคาร (ก้อนหลัง)

ตรวจ payload ที่หน้าจอสร้างจริงแล้วถอด TLV กลับได้ครบ:
AID `A000000677010111` · เบอร์ `0066812345678` · สกุล `764` · ยอด `45.00` ·
POI `12` (ล็อกยอด ลูกค้าแก้ไม่ได้) · CRC ผ่าน

### 1.6 ออฟไลน์ + ซิงก์ — บางส่วน

- [x] Dexie schema
- [x] คิวส่ง (outbox) แบบรักษาลำดับ + exponential backoff
- [x] แปลง error "ซ้ำ" เป็นสำเร็จ (กันคิวตันเมื่อคำตอบหายกลางทาง)
- [x] `storage.persist()`
- [x] ซิงก์ขาลงของเมนู — ดึงเฉพาะที่ `updated` ใหม่กว่าครั้งก่อน
      พร้อมกวาดทั้งหมดเป็นครั้งคราวเพื่อลบรายการที่ถูกลบบนเซิร์ฟเวอร์
- [x] จองช่วงเลขบิลที่เซิร์ฟเวอร์ก่อนบันทึกลงเครื่อง
- [ ] ซิงก์ขาลงของบิล (ต้องใช้ตอนร้านมี 2 เครื่อง และตอนทำรายงาน)

### 1.7 QR Order — บางส่วน

- [x] หน้าสั่งอาหารประจำโต๊ะ + ยืนยันเลขโต๊ะ
- [x] ตะกร้าใน localStorage แยกตามร้านและโต๊ะ
- [ ] **ตรวจลายเซ็น HMAC ของลิงก์โต๊ะ** (ปิดกั้นการส่งออร์เดอร์จนกว่าจะทำ)
- [ ] **คำนวณยอดเงินฝั่งเซิร์ฟเวอร์** — ห้ามเชื่อยอดจากไคลเอนต์
- [ ] จำกัดจำนวนออร์เดอร์ต่อนาทีต่อโต๊ะ
- [ ] รอบนั่งโต๊ะ — เปิด/ปิดรอบ
- [ ] ออร์เดอร์ขึ้นที่แท็บเล็ต POS พร้อมเสียงเตือน
- [ ] ปุ่มเรียกพนักงาน

## หนี้ทางเทคนิคที่รู้ตัวแล้ว

| เรื่อง                                             | ความเร่งด่วน                    |
| -------------------------------------------------- | ------------------------------- |
| `orders.createRule` เปิดให้สร้างบิล QR โดยไม่ตรวจลายเซ็น | **ก่อนเปิดให้ร้านจริงใช้**       |
| ยอดเงินคำนวณฝั่งไคลเอนต์ เซิร์ฟเวอร์ไม่ตรวจซ้ำ        | **ก่อนเปิดให้ร้านจริงใช้**       |
| พนักงานแก้ราคาเมนูได้ (ควรแก้ได้แค่ "ของหมด")        | ก่อนมีร้านที่มีพนักงานหลายคน     |
| ไม่มี apple-touch-icon เป็น PNG                     | ก่อนทดสอบบน iPad จริง            |
| PBKDF2 ใช้ crypto.subtle ซึ่งต้องเป็น https หรือ localhost | ก่อนทดสอบบนแท็บเล็ตจริงในวงแลน |
| บันเดิลหน้าลูกค้า 86 kB (gzip) — ตัด react-router ได้ | เมื่อมีร้านที่สัญญาณแย่จริง       |
| บันเดิลหน้าขาย 131 kB (gzip) — แยก qrcode ออกเป็น chunk ได้ | เมื่อแท็บเล็ตรุ่นถูกเปิดช้าจริง |
| หน้าขายยังไม่มีจอดูบิลย้อนหลัง/แก้บิล (ตรรกะพร้อมแล้ว) | ก่อนร้านนำร่องใช้จริง             |
| ยังไม่ตั้งสำรองข้อมูลรายวันออกนอกเครื่อง             | ก่อนมีข้อมูลการขายจริงใบแรก      |
